# S3-compatible raw storage for ONS jobs

ONS refresh, raw-only loading and deferred transformation can use the existing
`S3BlobStore` adapter for raw objects. Curated Parquet, ingestion receipts, batch
audits and saved-job history remain under the local `--output-root`. No database
provider, hosted account or new runtime dependency is required.

## Load into a local Garage service

The project's [Garage bootstrap](../infra/garage/bootstrap.sh) supplies a local bucket and
development credentials. From the repository root, start it and load that environment:

```bash
sh infra/garage/bootstrap.sh
set -a
. infra/garage/dev.env
set +a
cd python
poetry install --extras serving

# Use an independently selected full commit and its trusted registry handoff.
poetry run data-platform-lab ons-pay-refresh \
  --fetch-source ../handoffs/ons.json "$ONS_REGISTRY_COMMIT" \
  --backend s3 --bucket "$DPL_S3_BUCKET" \
  --endpoint-url "$DPL_S3_ENDPOINT_URL" --region "$AWS_DEFAULT_REGION" \
  --key-prefix ons/raw --output-root ../data \
  --reuse-verified --load-only --save-job ../jobs/ons-s3-load.json --dry-run

# Remove --dry-run to save the configuration, then execute it separately.
poetry run data-platform-lab ons-pay-refresh --job ../jobs/ons-s3-load.json
```

`--save-job` prepares configuration only. For a direct run, omit `--save-job` and
`--dry-run`. Omit `--load-only` to ingest and curate in one invocation. Checkout
sources (`--source HANDOFF CHECKOUT`) also support S3; saved jobs can mix checkout
and HTTPS sources. All source pins, checksum/size checks and freshness gates remain.

`--reuse-verified` verifies existing S3 bytes and downloads only missing raw
objects from the pinned source. It still contacts S3; it is not an offline mode.
Corrupt stored objects fail without automatic repair. Ingestion receipts retain
canonical storage keys and record `s3://<bucket>/<prefix>/<key>` destination URIs.

## Explicit locations and runtime authentication

| Option | Meaning |
| --- | --- |
| `--backend s3` | Select S3 raw storage; the default remains local. |
| `--bucket` | Required explicit bucket, using a lowercase 3–63 character name. The bucket must already exist. |
| `--endpoint-url` | Optional HTTP(S) service endpoint; omit for the SDK's standard S3 endpoint selection. |
| `--region` | Optional signing region; otherwise use the SDK's region configuration. |
| `--key-prefix` | Optional literal namespace, such as `ons/raw`; default empty. |

ONS commands do not read `DPL_S3_*` variables as implicit location defaults. Pass
them explicitly as in the example so a saved job records the selected location.
S3 settings require `--backend s3`, and `--object-root` cannot accompany it.
Endpoints cannot contain user information, query strings, fragments or service
paths. Prefixes must be normalized relative object keys without traversal.

Credentials are resolved by the existing boto3 SDK credential chain at execution,
including environment credentials and temporary session tokens. There are no
credential CLI flags or job fields. Dry-run and job preparation validate metadata
without constructing an S3 client, reading credentials, opening a store or creating
destination directories. They do not check bucket existence, permissions or remote
availability. Storage initialization errors exit `1` with a fixed diagnostic and
can occur before any batch audit exists; retain invocation exit codes as well.

## Save and transform later

S3 jobs use this alternative to the local `object_root` field:

```json
"object_store": {
  "backend": "s3",
  "bucket": "data-platform-lab",
  "endpoint_url": "http://localhost:3900",
  "region": "garage",
  "key_prefix": "ons/raw"
}
```

Keep the usual `schema_version`, sources and local `output_root`. Exactly one of
`object_root` and `object_store` is required. Unknown settings and credential fields
are rejected. `--job` cannot be combined with storage overrides. Existing local
jobs and their generated bytes remain unchanged. Changing a storage location changes
the saved-job digest and starts a separate completed-run history.

Use a successful load audit and the same S3 location for deferred transformation:

```bash
poetry run data-platform-lab ons-pay-transform \
  --load-audit ../data/manifests/ons_pay_load_<run-id>.json \
  --backend s3 --bucket "$DPL_S3_BUCKET" \
  --endpoint-url "$DPL_S3_ENDPOINT_URL" --region "$AWS_DEFAULT_REGION" \
  --key-prefix ons/raw --output-root ../data
```

Add `--dry-run` for metadata-only preflight. Execution reads and revalidates raw
bytes from S3, runs the existing model checks and writes local Parquet. No source
HTTP download or original handoff is required. `ons-pay-job-status` and curated
monitoring continue to inspect local evidence. `ons-pay-load-verify` currently
supports local raw storage only.

## Coordination and limits

The local output root keeps its existing process guard. It does not lock an S3
bucket or coordinate writers on other hosts or different local output roots.
Coordinate writers sharing a bucket/prefix; this is not a distributed transaction.
Earlier successfully loaded objects survive a later batch failure. Source-fetch
retry flags control source HTTPS requests; S3 operations use the existing adapter
and SDK behavior. The adapter reads a raw object into memory for checksum checks.

The Python configuration `S3Storage` in `data_platform_lab.storage.config` validates
and serializes locations without connecting. Its `open()` method constructs the
existing adapter. `prepare_refresh_job` accepts `object_store=S3Storage(...)` with
`object_root=None`; parsed S3 jobs return those same fields. Core refresh and
transformation still consume the existing `BlobStore` protocol.

Offline tests use the S3 adapter with an in-memory client. The S3 CI workflow also
runs load-only/full saved jobs, verified replay and deferred transformation against
disposable Garage. Live tests require `ONS_PAY_LIVE_S3=1`, reject hosted endpoints
and clean up only their own randomly named prefixes.
